Security Architecture & Cryptographic Trust

Defense-in-depth principles engineered to guarantee whistleblower confidentiality and institutional integrity.

1. High-Entropy Unpredictable Tracking Codes

Instead of simple sequential complaint numbers (e.g. #1001, #1002) which are trivial to enumerate, CaseBridge generates unpredictable 16-character keys formatted as CB-XXXX-XXXX-XXXX.

The 12 random alphanumeric characters are selected using Python's cryptographically secure pseudo-random number generator (secrets.choice) from an unambiguous character alphabet that excludes visually similar characters (omitting 0, O, 1, and I).

Keyspace Entropy: 32^12 ≈ 1.15 × 10^18 possible permutations

2. Irreversible One-Way Hash Storage (SHA-256 + Pepper)

The plain tracking code is only returned to the student once in the submission response. In our database, the column tracking_hash stores a SHA-256 digest computed with an application-level server pepper:

digest = SHA-256(tracking_code + TRACKING_CODE_SALT)

Even if an adversary were to gain read access to the database tables, they could not derive the plain tracking codes to access active student communication threads.

3. Application-Level Field Encryption at Rest (AES-256 / Fernet)

Sensitive complaint text (cases.narrative) and two-way messages (messages.message_content) are encrypted before being written to the database engine using symmetric AES-256 (Fernet) keys loaded from server-side environment secrets.

Non-sensitive metadata (category, status, priority, creation date) remains unencrypted to allow fast, indexed institutional filtering without sacrificing narrative confidentiality.

4. Anti-Enumeration & Rate-Limiting Controls

The tracking lookup endpoint (/track) is strictly bounded by moving-window rate limits (maximum 20 queries per minute per client). Rapid non-matching queries incur temporary client lockouts.

Furthermore, error messages returned for non-existent codes give identical, safe feedback without revealing whether nearby tokens exist.

5. Role-Based Access Control (RBAC) & Tamper-Evident Event Logs

Institutional access is strictly partitioned into three roles: Committee Member, Committee Lead, and System Administrator. Staff passwords are protected with modern Scrypt key-derivation functions.

Every status transition, assignment change, and escalation triggers an immutable entry in case_events capturing the actor role, timestamp, and safe metadata. Staff members cannot alter or delete past historical events.
